<p>把时间轴摊开看，投流团队在 IP 管理上真正要做的动作只有五次：上号前一周、前三天、上线当天、满七天、满三十天。其余时间都是在执行这五次定下来的规矩。按时间顺序走一遍，比背一堆原则管用，因为每个节点都有明确的交付物，做完就算过，做不完就别往下走。</p>

<h2>一、T-7 天：把资源和责任先分好</h2>
<p>提前一周只做两件事：出口到位、责任人到位。这两件没落地，后面所有配置都是临时抱佛脚。</p>
<h3>出口清单按「账号—地区—用途」三列建</h3>
<p>每个在投账号对应一行，写清出口地址、所在地区、主用还是备用。清单不是给老板看的，是给三个部门对账用的：运营知道用哪条，财务知道为什么付这笔钱，技术知道故障时切哪条。</p>
<h3>责任人写名字，不写岗位</h3>
<p>「由运营负责」这种描述等于没人负责。写具体的人，加一个备份人，两个人都不在时指定临时代理人。权限交接时，这张表就是交接单。</p>

<h2>二、T-3 天：环境对齐与连通性验收</h2>
<p>提前三天把所有配置跑一遍，别等到上线当天。这一步的产出是一份验收记录，逐项签字或打勾。</p>
<h3>四项验收：连通、归属、时区、延迟</h3>
<p>连通看能不能正常建连；归属看国家城市是否与订单一致；时区看系统与浏览器是否同步；延迟看首字节时间是否稳定。四项里任何一项不过，退回服务商换线，别自己想办法凑合。</p>
<h3>把验收结果存成截图或日志</h3>
<p>截图不是形式主义。同一条线在第三天正常、第七天异常，有当时的记录就能判断是服务商的问题还是自己改坏了，扯皮时省一半口水。</p>

<h2>三、上线当天：三条硬规矩</h2>
<p>上线当天最容易乱，因为所有人都在赶进度。这时候只保留三条规矩，其他都可以往后放。</p>
<h3>规矩一：一个号只从一条线登录</h3>
<p>当天不管谁值班，都从清单上指定的那条线进。临时借用别人的线路，是当天最常见的破坏性操作，一次借用就能把两条记录绑在一起。</p>
<h3>规矩二：当天不改资料、不换设备</h3>
<p>上线当天只做投放动作，不改密码、不改电话、不加新设备。新环境需要先建立一段平稳的登录记录，改动越多越像异常。</p>
<h3>规矩三：所有操作留时间戳</h3>
<p>谁在几点做了什么，用表格记一行就够。不需要复杂系统，一个共享表格加时间列，事后能还原当天发生了什么。</p>

<h2>四、T+7 天：第一次复盘看什么</h2>
<p>满七天做第一次复盘，重点不是看业绩，是看环境有没有出过状况。业绩受素材和出价影响太大，环境问题才是这一阶段能控的变量。</p>
<h3>看三类记录：验证次数、切换次数、掉线次数</h3>
<p>验证次数上升说明环境可信度在下降；切换次数多说明线路不稳；掉线次数要区分是本地网络还是出口问题。三个数放在一张表里看趋势，比单看某一天有意义。</p>
<h3>该换的线在第七天换，不要拖</h3>
<p>发现某条线在七天内出现两次以上异常，直接换，别等它「再看看」。测试期换线的成本最低，等投放跑起来再换，影响的是真金白银。</p>

<h2>五、T+30 天：交接、轮换与归档</h2>
<p>一个月是个合适的节点，该复核的复核，该归档的归档。很多团队的问题不是出在配置，是出在人走了权限还在。</p>
<h3>离职当天必须完成的三件事</h3>
<p>收回出口配置权限、更换该成员经手账号的登录凭据、把其名下的操作记录归档。三件事当天做完，别留到下周。权限回收晚一天，风险就多一天。</p>
<h3>出口要不要跟着换</h3>
<p>成员离职不必换出口，出口是绑账号的，不是绑人的。只有当该成员同时掌握多条线路的完整凭据、且存在外泄可能时，才需要整体更换。</p>
<h3>归档保留多久</h3>
<p>建议登录与操作记录至少保留六个月，涉及资金与合同的材料按财务要求保存。归档不是堆积，按「账号—月份」两级目录存放，找的时候能在两分钟内定位。</p>

<h2>常见问答</h2>
<h3>小团队也需要这么完整的时间线吗？</h3>
<p>答：节点可以合并，动作不能省。三个人的团队可以把 T-7 和 T-3 压到两天里做完，但验收记录和责任人这两项必须留下。</p>
<h3>上线当天发现线路不通，能临时换一条吗？</h3>
<p>答：能换，但要按流程换：记录更换时间与原因，换完当天不再动其他配置。临时换线本身不是问题，换完又改设备才是。</p>
<h3>操作留痕要记到什么颗粒度？</h3>
<p>答：记到「谁、何时、对哪个号、做了什么动作」四要素即可。不需要记录每一次点击，重点是能还原关键动作的顺序。</p>
<h3>三十天复盘的结论要落到哪里？</h3>
<p>答：落到下一轮的出口清单上。复盘的唯一产出应该是清单的修订版，否则下次还是同一批问题重复出现。</p>

<h2>合规提示</h2>
<p>团队在管理投放账号与网络资源时，应建立内部权限与审计制度，遵守平台服务条款、广告法及个人信息保护相关法规。操作记录的留存应限于业务必要范围。</p>
<p>本文不提供规避平台监管、隐瞒真实经营主体或伪造操作记录的方法。权限回收与记录归档的目的在于合规审计与风险追溯。</p>
<p>文中时间节点为通用建议，具体周期请结合自身业务节奏与合同约定调整。</p>
